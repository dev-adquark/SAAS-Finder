# SaaSFinder

SEO-first SaaS reviews, alternatives, comparisons and best-for guides. Next.js 16 (App Router, ISR) + Prisma + PostgreSQL.

## Page types and canonical URLs

All URLs are generated by one registry, [`lib/seo/routes.ts`](lib/seo/routes.ts).

| Page | URL | Template |
| --- | --- | --- |
| Category hub | `/category/{slug}` | `app/category/[slug]` |
| Product review | `/{product-slug}` | `app/[slug]` |
| Alternatives | `/alternatives/{product-slug}` | `app/alternatives/[productSlug]` |
| Comparison | `/compare/{a}-vs-{b}` (alphabetical; reverse order 308-redirects) | `app/compare/[slugs]` + `proxy.ts` |
| Best-for guide | `/best/{use-case-slug}` | `app/best/[slug]` |
| Indexes | `/products`, `/categories`, `/comparisons`, `/alternatives`, `/best` | |
| Compliance | `/methodology`, `/disclosure`, `/privacy`, `/contact` | |

Rules:

- Product slugs can't use reserved top-level routes or contain `-vs-`.
- Only curated comparison pairs exist, so there are no auto-generated thin pages.
- Legacy `/products/{slug}` and `/categories/{slug}` URLs permanently redirect.
- Canonicals never carry query strings.

## Architecture

- **Content model** (`prisma/schema.prisma`): Category, Product, ReviewMetadata, Tag/ProductTag, Alternative (the curated alternatives set, with a rationale for each entry), CompetitorPair, UseCase/UseCaseProduct, and Faq (owned by a product, category or use case).
  - Pricing, links, history and freshness: PricingSnapshot (plan, price, currency, billing period, source, verification status), AffiliateLink, ChangeLog and ContentRefresh.
  - Commercial and analytics: SponsorSlot and AnalyticsEvent.
  - The database enforces integrity with foreign keys and CHECK constraints: FAQ ownership, no self-alternatives, no reverse duplicate pairs, and valid price and rating ranges.
- **Catalog** (`lib/catalog.ts`) loads everything once per request and passes it through `sanitizeCatalog`, so public pages only ever link to published, consistent content.
  - With a database it reads Postgres.
  - Without one, it renders the bundled editorial seed (`lib/content/seed/*`).
- **Internal linking engine** (`lib/linking.ts`) produces the crawlable link groups for every page type.
- **Admin** (`/admin`): a server-rendered UI with HMAC-signed session cookies, backed by the same service layer (`lib/admin/services.ts`) as the bearer-token JSON API (`/api/admin/*`).
  - Covers products, categories, best-for, alternatives, comparisons, pricing review, affiliates, sponsors, refreshes and analytics.
  - Publishing is blocked until required fields are complete.
  - Published content can't be hard-deleted.
- **Monetization**:
  - Every CTA goes through `/go/{slug}` with campaign metadata. The redirect only uses stored URLs: a verified, active HTTPS affiliate link, or else the official URL.
  - Affiliate links use `rel="sponsored nofollow"` and are labelled, and pages with CTAs show a visible disclosure.
  - Sponsor slots are served at view time, always labelled "Sponsored", tracked separately through `/sponsor/{id}`, and never read by editorial logic.
- **Analytics**: `page_view`, `cta_click`, `outbound_click`, `sponsor_click` and `cpl_submit`.
  - Payloads are validated, size-limited and stripped of PII.
  - Storage failures are swallowed.
  - Admin reporting supports a date range and shows event, product, CTA and sponsor breakdowns.

## Pricing and freshness workflow

1. A published product has a freshness target: 90 days by default, with a per-product override.
2. The daily cron (`/api/cron/content-refresh`, secured by `CRON_SECRET`) queues refresh tasks for products that have never been verified or are overdue. It never scrapes or edits pricing.
3. An editor checks the official pricing page, then does one of two things:
   - marks the task **Checked — no change**, which updates "Last checked" and writes a change-log entry;
   - records a new snapshot and **verifies** it.
4. Verifying a snapshot:
   - supersedes the previous price for that plan;
   - updates "Last checked";
   - writes a change-log entry;
   - closes open tasks;
   - revalidates pages.
5. Automated detections are always `PENDING`, and only `VERIFIED` snapshots render. With no verified price, pages show "Pricing varies — check the official pricing page."

## Local development

```bash
npm install
cp .env.example .env.local   # fill in values; DATABASE_URL optional
npx prisma generate
npx prisma migrate deploy    # when DATABASE_URL is set
npm run db:seed              # create-only: never overwrites existing rows
npm run dev
```

`npm run db:seed:refresh` re-applies the seed's editorial copy to seed-owned records. It never deletes pricing history, affiliate links, sponsors or analytics.

## Tests

| Command | What it covers |
| --- | --- |
| `npm test` | Unit, SEO, linking and API-validation tests (no database needed) |
| `TEST_DATABASE_URL=... DATABASE_URL=$TEST_DATABASE_URL npm run test:db` | Migrations, seed and database integration tests. Use an **empty, disposable** database. |
| `BASE_URL=http://localhost:3000 npm run test:e2e` | Crawls the sitemap and every internal link. Checks canonicals, metadata, JSON-LD, disclosures and redirects, and walks the home → category → product → alternatives → compare → best-for → CTA journey. |
| `BASE_URL=... ADMIN_API_KEY=... npm run test:admin-e2e` | The admin UI through real form posts |

CI (`.github/workflows/ci.yml`) runs all of these, with a Postgres service for the database job.

## Production environment

| Variable | Required | Notes |
| --- | --- | --- |
| `DATABASE_URL` | yes | Postgres. On serverless, use the provider's **pooled** URL, e.g. Supabase transaction pooler `:6543?pgbouncer=true`. The pool size is capped automatically unless `connection_limit` is set. |
| `NEXT_PUBLIC_SITE_URL` | yes | Canonical origin, no trailing slash. The build fails without it. |
| `ADMIN_API_KEY` | yes | At least 16 characters (`openssl rand -base64 32`). Used as the admin password and API bearer token. |
| `CRON_SECRET` | yes | Vercel Cron sends `Authorization: Bearer <CRON_SECRET>`. |
| `CONTACT_EMAIL` | recommended | While unset, `/contact` is noindex and left out of the sitemap. |

### Deploy (Vercel)

1. Set the variables above for Production.
2. Run `npx prisma migrate deploy`, then `npm run db:seed`, against the production database once (and `migrate deploy` on every schema change).
3. Deploy. `vercel.json` schedules the freshness cron daily at 03:00 UTC.
4. Smoke test:
   - `/api/health`
   - `/sitemap.xml`
   - `/robots.txt`
   - a product page
   - `/go/{slug}`
   - `BASE_URL=https://your-domain npm run test:e2e`

## Launch inputs only the business can supply

The code never invents any of these; it ships with safe empty or fallback states until they exist:

- **Verified vendor pricing.** Seed pricing notes are `PENDING` until an editor verifies them.
- **Hands-on reviews.** Seed profiles are marked "hands-on review pending", and Review schema is only emitted once a review is marked `REVIEWED`.
- **Real affiliate partner links**, and any sponsor or CPL agreements.
- **Legal entity details, a monitored contact inbox, and final privacy/cookie language.**
- **The production domain, database credentials and secrets.**
